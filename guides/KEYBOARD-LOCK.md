# 전체화면 단축키 연습 검사

## 지원 조건과 한계

- HTTPS(또는 개발용 localhost)의 최상위 페이지에서 Fullscreen API와 `navigator.keyboard.lock/unlock`를 제공하는 환경이 필요합니다. 지원되는 데스크톱 Chromium 계열 Chrome/Edge에서 기능을 감지합니다. 모바일·다른 브라우저의 지원을 가정하지 않습니다.
- 사이트의 전체화면 시작 버튼을 직접 클릭해야 합니다. F11로 켠 브라우저 전체화면과 JavaScript Fullscreen API는 다릅니다.
- 성공 안내는 실제 `lock(codes)` Promise 완료 후에만 표시합니다. 거절·조직 정책·미지원은 대체 안내로 돌아갑니다.
- Chrome의 권한 도입 안내에는 철회 경고가 추가되어 있습니다. 특정 버전부터 권한창이 항상 뜬다고 단정하지 않으며, API 요청 결과로 판단합니다.
- 운영체제 예약 키, 하드웨어 Fn/미디어 키, 보안상 제한된 키는 보장하지 않습니다. Esc는 잠금 대상에서 제외합니다. 일반 Esc가 작동하지 않는 환경은 브라우저의 전체화면 종료 UI나 길게 Esc를 눌러 빠져나오세요.

## 자동 모의 검사

`npm run check`와 `npm test`를 실행합니다. `tests/keyboard-lock-test.cjs`는 전체화면·잠금 API를 모의하여 다음을 검사합니다.

- 클릭으로만 요청, fullscreen → lock 순서, Promise 대기 중 성공 표시 금지
- 미지원·안전하지 않은 컨텍스트·권한 거절·전체화면 실패·종료 실패
- 중복 요청/이벤트 등록 방지, 취소 후 늦게 완료되는 요청 정리
- 전체화면 종료·페이지 숨김·blur·pagehide·훈련 종료·화면 전환, 자동 재잠금 금지
- 기존 판정기에서 실제 셀·시트·계산·저장·대화상자 변화와 XP 한 번 지급
- 수식 편집·붙여넣기·리본·개인 QAT·Ctrl 보조·일반 텍스트 입력 보존
- 잠금 시작·종료·실패에서 기존 localStorage 바이트 보존

이 검사는 모의 이벤트 전달 이후의 앱 동작을 검증합니다. OS나 브라우저가 예약한 물리 키를 실제로 앱에 전달하는지는 아래 수동 검사로 별도 확인해야 합니다.

## 실제 Chrome/Edge 검사 절차

1. 별도 테스트 프로필에서 운영 사이트를 열고 브라우저·버전·OS·키보드 기종·Fn 설정을 기록합니다. 기존 사용자 데이터는 지우지 않습니다.
2. 필요한 경우 이름을 입력합니다. 전체 목록의 기능을 선택하려면 회계 실무 집중 모드를 전체 학습으로 바꾸고 배우기에서 한 기능을 선택합니다.
3. Ctrl 보조 입력을 끄고 **전체화면 단축키 연습 시작**을 클릭합니다. 전체화면과 활성화 성공 문구를 확인합니다. 권한창이 있으면 허용/거절을 각각 검사합니다.
4. 아래 키를 실제 키보드로 입력합니다. JavaScript로 `dispatchEvent`한 입력은 이 검사의 대체가 아닙니다. 도움말·개발자도구·브라우저 탭·새로고침·브라우저 인쇄/저장이 실행되는지 함께 확인합니다.

| 입력 | 준비/기대 결과 |
| --- | --- |
| F1 | 도움말 학습 → 실습 도움말 창 |
| F2 | 셀 편집 학습 → 수식 입력줄에서 편집 |
| F4 | 절대참조 학습 → `=D3*$H$2` |
| F5 | 이동 창(F5) 학습 → 이동 창 → F3 입력·Enter → 실제 F3 선택 |
| F9 | 모두 계산 학습 → F3의 24,000이 48,000으로 재계산 |
| F12 | 다른 이름 저장 학습 → 실습 이름 입력·Enter → 브라우저에 실습본 저장 |
| Ctrl+PageDown | 다음 시트 학습 → Sheet1에서 Sheet2, D2=830,000 |
| Ctrl+PageUp | 이전 시트 학습 → Sheet2에서 Sheet1, D2=1,250,000 |
| Ctrl+S | 저장 학습 → 실습 상태 저장; 자유 실습의 저장된 실습본 열기로 복원 |
| Ctrl+P | 인쇄 학습 → 앱의 인쇄 미리보기 |

5. 각 학습에서 키를 길게 눌러도 XP가 한 번만 증가하는지 확인합니다. 대화상자의 Enter가 다음 미션으로 넘어가면 실패입니다. 자유 실습에서는 XP가 증가하면 안 됩니다.
6. 수식 입력 중 F4, 편집 초안 작성 후 Ctrl+S, 선택하여 붙여넣기에서 V → Enter, Alt 리본 순서, 본인 QAT 번호를 확인합니다. 일반 이름·대화상자 입력에서는 문자를 자유롭게 입력할 수 있어야 합니다.
7. 종료 버튼과 Esc를 각각 검사합니다. 다른 탭·앱으로 이동하고 돌아와도 잠금이 자동 재활성화되면 안 됩니다. 시작 버튼을 다시 클릭해 재시작합니다. 진행 중 미션·셀·시트·학습 기록이 보존되어야 합니다.
8. 전체화면 진입 거부 또는 API 미지원 브라우저에서 대체 문구·Ctrl 보조·Fn 안내와 일반 학습이 작동하는지 확인합니다.
9. 큰 화면과 좁은 창에서 미션·종료 버튼·실습 셀·시트 탭·정답 피드백이 함께 보이는지 확인합니다. 행·열이 넘치면 실습 그리드 내부를 스크롤합니다.

아직 실행하지 않은 OS·브라우저·물리 키보드 조합은 미검증으로 기록합니다. API 성공만으로 모든 시스템 단축키의 전달을 보장하지 않습니다.
